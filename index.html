The workflow

Three steps from unfamiliar change to confident review.

Keystone is designed for the moment when a pull request touches an area nobody wants to claim they understand.

1

Connect knowledge

Ingest merged pull requests, reviewers, authors, and touched files into FalkorDB. Keystone learns from the repository's actual review history.

2

Ask about a PR

Choose a repository and enter a pull request number. The graph traces file overlap, recent context, and knowledge concentration.

3

Act with evidence

Get a ranked reviewer, clear risk flags, and a safe sandbox plan. You stay in control of every action.

Connect real repository data

Bring a GitHub repository into Keystone.

Paste a public GitHub repository URL. Keystone will fetch its real merged PRs, changed files, authors, and submitted reviews into FalkorDB. Existing PRs are skipped, so you can safely resume.

How repository data gets here

Keystone does not guess from a code snippet. An operator first ingests a repository's merged PR history into FalkorDB.

  1. 01Set FalkorDB and GitHub credentials in .env.
  2. 02Run python ingest.py once for the repository.
  3. 03Return here, choose the repository, and analyze a PR.
